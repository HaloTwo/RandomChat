반드시 모든 설명과 최종 답변을 한국어로 작성한다.

이 명령의 목적은 RandomChat 프로젝트의 현재 실제 구현 상태,
README 진행 내역, 최신 Notion 기획 정보를 종합해서
현재 어디까지 개발되었는지 상세하게 정리하는 것이다.

중간 작업 하나를 완료했다고 종료하지 않는다.

파일을 읽거나 작성한 뒤
"추가로 무엇을 할까요?"라고 사용자에게 묻지 않는다.

아래의 모든 확인 작업과 최종 상세 보고까지 완료해야
/update 작업이 끝난 것이다.


# 절대 규칙

프로젝트 정보를 추측해서 생성하지 않는다.

실제 README, 실제 소스코드, 실제 Notion 응답에서
확인할 수 없는 내용을 사실처럼 작성하지 않는다.

특히 다음 내용을 임의로 만들어내지 않는다.

- 사용 중인 프레임워크
- API Endpoint
- 서버 구조
- 데이터베이스 구조
- 구현 완료 기능
- 예정 기능
- 프로젝트 구조
- 기술 스택

프로젝트 경로를 임의로 변환하지 않는다.

다음과 같은 경로를 만들지 않는다.

- `/workspace`
- `/home/user`
- `C:\workspace`

프로젝트 루트 기준 상대경로만 사용한다.

Skill 도구를 사용하지 않는다.
존재하지 않는 `find_files` 같은 기능을 만들지 않는다.


# 실제 README

아래 내용은 현재 프로젝트의 실제
`ProjectRC/README.md` 내용이다.

README를 다시 read 도구로 읽으려고 하지 않는다.

```text
!`powershell -NoProfile -Command "$p='ProjectRC\README.md'; if (Test-Path $p) { Get-Content -Raw -Encoding UTF8 $p } else { '[README_NOT_FOUND]' }"`
```


# 기존 Notion 캐시

아래 내용은 기존 Notion 로컬 캐시다.

캐시가 아직 존재하지 않으면 `[NO_NOTION_CACHE]`가 표시된다.

```text
!`powershell -NoProfile -Command "$p='knowledge\notion\randomchat.md'; if (Test-Path $p) { $c=Get-Content -Raw -Encoding UTF8 $p; if ($c) { $c } else { '[NO_NOTION_CACHE]' } } else { '[NO_NOTION_CACHE]' }"`
```

`[NO_NOTION_CACHE]`가 표시되면
존재하지 않는 캐시 파일을 읽으려고 하지 않는다.

`cache.json`, `project.json`, `notion.json` 등의
임의 파일명을 만들지 않는다.


# 1. README 분석

위 README 실제 내용을 분석한다.

다음 내용을 파악한다.

- 프로젝트 목적
- 현재까지 구현한 기능
- 현재 동작 가능한 기능
- 작업 중인 기능
- TODO 또는 미완료 기능
- README에 기록된 기술적 결정
- README에 기록된 문제점
- 향후 개발 계획

README에 없는 내용을 추측하지 않는다.


# 2. 최신 Notion 확인

Notion MCP를 사용할 수 있으면
RandomChat 원본 페이지를 직접 읽는다.

사용 가능한 Notion 도구 중
다음 도구만 사용한다.

`notion_notion-fetch`

다른 Notion 도구를 탐색하거나 호출하지 않는다.

특히 다음 기능을 사용하지 않는다.

- notion search
- search-agents
- search-skills
- Custom Agent
- Session
- get-tool-access
- 다른 Notion 페이지 검색

RandomChat Notion 원본:

`https://app.notion.com/p/04-3dd4a21a8b6781da8601ce1b9e3789fe`

`notion_notion-fetch` 호출 시
반드시 `id` 인자에 위 전체 URL을 넣는다.

올바른 의미:

`id = "https://app.notion.com/p/04-3dd4a21a8b6781da8601ce1b9e3789fe"`

다음 인자는 사용하지 않는다.

- `url`
- `page_url`


# 3. Notion 캐시 갱신

Notion fetch가 실제로 성공하고
실제 페이지 내용이 반환된 경우에만 캐시를 갱신한다.

저장 위치:

`knowledge/notion/randomchat.md`

캐시에는 실제 Notion에서 확인된 정보만 저장한다.

가능하면 다음 내용을 정리한다.

- 원본 Notion URL
- 페이지 제목
- 동기화 시각
- 프로젝트 목표
- 기능 요구사항
- 구현 예정 기능
- 개발 방향
- 프로젝트 메모
- 우선순위
- README와 비교했을 때 새로 추가된 내용

Notion에서 확인하지 못한 내용을
임의로 추가하지 않는다.

Notion fetch가 실패하면:

- 기존 캐시를 덮어쓰지 않는다.
- 새 캐시 내용을 만들어내지 않는다.
- 같은 실패 호출을 반복하지 않는다.
- README와 기존 캐시를 기준으로 다음 단계로 진행한다.

캐시 작성 또는 갱신이 끝났다고
/update 작업을 종료하지 않는다.


# 4. README와 Notion 비교

README와 최신 Notion 내용을 비교한다.

README는 현재까지의 개발 진행 내역을 파악하는 자료로 사용한다.

Notion은 프로젝트 기획과
앞으로 구현해야 할 기능을 파악하는 자료로 사용한다.

둘을 비교해서 다음을 구분한다.

- README와 Notion 모두 완료로 판단되는 기능
- README에는 있지만 Notion에 없는 구현
- Notion에는 있지만 아직 README에 완료 기록이 없는 기능
- 구현 예정 기능
- 요구사항이 변경된 부분
- 서로 내용이 충돌하는 부분

내용이 충돌하면 임의로 어느 한쪽이 맞다고 결정하지 않는다.

필요하면 최종 보고의 "확인 필요 사항"에 표시한다.


# 5. 실제 코드 검증

README와 Notion만으로
특정 기능의 실제 구현 여부가 명확하지 않은 경우에만
`ProjectRC/`의 실제 소스코드를 확인한다.

코드를 확인할 때는
현재 프로젝트 루트 기준 상대경로만 사용한다.

실제 코드에 존재하지 않는 기능을
완료된 기능이라고 판단하지 않는다.

반대로 README에 기록되지 않았더라도
실제 코드에서 명확히 구현된 기능을 발견하면
"코드에서 추가 확인된 구현"이라고 구분해서 표시한다.

대규모 전체 코드 분석은 하지 않는다.

진행 상황 판단에 필요한 코드만 확인한다.


# 6. 구현 상태 판단 기준

현재 기능이 구현되었는지 판단할 때 우선순위:

1. 실제 코드
2. ProjectRC/README.md
3. 최신 Notion
4. 기존 knowledge/notion 캐시

앞으로 무엇을 구현해야 하는지 판단할 때 우선순위:

1. 최신 Notion
2. README의 TODO
3. 현재 실제 코드 상태
4. 기존 Notion 캐시


# 7. 최종 상세 보고

반드시 아래 형식으로 상세하게 답변한다.

단순히 한두 줄로 끝내지 않는다.

## 동기화 상태

다음을 각각 표시한다.

- README 확인: 성공 / 실패
- Notion 연결: 성공 / 실패
- 기존 Notion 캐시: 있음 / 없음
- Notion 캐시 갱신: 완료 / 미실행 / 실패
- 실제 코드 추가 확인: 수행 / 불필요

Notion 연결에 실패했다면
왜 실패했는지 한 줄 정도만 설명한다.


## 프로젝트 현재 상태 요약

현재 RandomChat이 전체적으로 어느 단계인지
3~6문장 정도로 설명한다.

예:

- 기초 구조 단계
- 핵심 기능 구현 단계
- 기능 확장 단계
- 안정화 단계
- 배포 준비 단계

단, 실제 확인 자료를 근거로 판단한다.


## 완료된 작업

실제로 완료된 기능을 가능한 구체적으로 정리한다.

각 항목은 단순 기능 이름만 적지 말고
현재 어느 정도까지 동작하는지 함께 설명한다.

README, 코드 또는 Notion 중
어디에서 확인했는지도 필요하면 짧게 표시한다.


## 현재 구현 상태

현재 프로젝트가 실제로 실행했을 때
어떤 흐름까지 사용할 수 있는지 설명한다.

예를 들어:

- 사용자가 할 수 있는 행동
- 현재 동작하는 화면
- 데이터 저장 여부
- 사용자 간 상호작용 가능 여부
- 현재 테스트 가능한 범위

실제 자료에 있는 내용만 작성한다.


## 진행 중이거나 불완전한 부분

부분 구현되었거나
아직 완성되지 않은 기능을 구분해서 적는다.

완전히 없는 기능과
일부만 구현된 기능을 구분한다.


## 남은 작업

Notion 기획과 README를 기준으로
앞으로 구현해야 할 내용을 정리한다.

가능하면 다음 정도로 구분한다.

- 반드시 필요한 핵심 작업
- 기능 완성도를 높이는 작업
- 나중에 해도 되는 작업


## README와 Notion 차이

두 자료 사이에 차이가 있으면 정리한다.

예:

- Notion에는 있으나 README에는 아직 없는 기능
- README에는 구현 완료라고 되어 있지만 Notion 요구사항이 변경된 기능
- 서로 표현이 달라 확인이 필요한 기능

차이가 없으면
"현재 확인된 주요 충돌 없음"이라고 작성한다.


## 확인 필요 사항

자료만으로 확정할 수 없는 부분이 있으면 적는다.

추측하지 않는다.

확인할 내용이 없다면
"현재 특별히 확인이 필요한 사항 없음"이라고 작성한다.


## 다음 작업

현재 상태에서 바로 이어서 진행하는 것이 자연스러운 작업을
최대 3개 정도 제시한다.

각 작업마다 다음 내용을 짧게 포함한다.

- 무엇을 구현할지
- 왜 지금 해야 하는지
- 어느 파일 또는 기능 영역과 관련 있는지

사용자에게 무엇을 할지 다시 묻기 전에
프로젝트 자료를 기준으로 가장 자연스러운 다음 작업을 먼저 제시한다.


# 완료 조건

아래 조건을 모두 만족해야 /update가 완료된 것이다.

- README 분석 완료
- 가능한 경우 Notion 최신 정보 확인
- 필요한 경우 Notion 캐시 갱신
- README와 Notion 비교
- 필요한 경우 실제 코드 확인
- 한국어 상세 진행 상황 보고 출력

중간에 파일을 작성했다고 종료하지 않는다.

다음과 같은 문장으로 끝내지 않는다.

- "무엇을 더 도와드릴까요?"
- "추가 작업이 있나요?"
- "어떤 작업을 원하시나요?"
- "프로젝트 정보를 알려주세요."

현재 자료를 기준으로
상세한 진행 상황 보고까지 작성하고 종료한다.
