# RandomChat 작업 재개 기록

## 최신 상태 · 2026-09-21

- 실제 공기계에서 APK 다운로드와 서버 접속을 확인했다. 서버 주소는 `http://192.168.0.2:3000`이다.
- Android 0.2은 **라운지 / 대화 / 내 설정** 탭과 카드형 화면으로 구성했다. APK는 `android/build/moment-local-debug.apk`이다.
- 서버 자동 테스트는 21개 통과했고 APK 빌드·서명과 `/app.apk` 응답을 확인했다.
- SQLite는 `data/`, 담당자 토큰은 Git 제외 `private/LOCAL_TOKENS.txt`로 분리했다. 토큰 원문을 문서·Git·Notion에 적지 않는다.
- 다음 실제 기기 확인: Android 0.2에서 라운지 글·랜덤 매칭·사진·영상 흐름을 각각 한 번씩 시험한다.
- Codex CLI에서는 `update` 또는 `update <할 일>`을 입력한다. 프로젝트의 `AGENTS.md`가 검사·구현·테스트·문서 갱신 순서를 제공한다.

## 2026-09-21 공기계 시험 준비

- `start-phone.cmd`에서 PC의 사설 IPv4를 골라 서버를 해당 주소에만 연다. 같은 공유기의 공기계 APK는 그 주소를 입력한다. `start.cmd`의 로컬호스트 모드와 동시에 실행하지 않는다.
- Android 앱은 사설 IPv4:3000 접속을 허용한다. 실제 기기 설치·통신은 아직 확인하지 못했다.
- README에 PC·공기계 설치/플레이/사진·영상 승인 순서, SQLite 별도 설치 불필요, `node db-view.js` 건수 조회를 적었다.
- `API_GUIDE.txt`에 토큰/API 설명을 두고 `node admin.js create-reviewer-to-file`이 새 담당자 토큰을 Git 제외 `private/LOCAL_TOKENS.txt`에 저장한다. 원문 토큰은 노션에 적지 않는다.
- 서버 통합 테스트 16개 통과. APK 재빌드·서명 검증 완료. PC 사설 주소 `192.168.0.2:3000`의 `/api/health`가 200 응답했다. 실제 공기계 연결은 미검증이다. 현재 PC 이더넷 네트워크 분류는 Public이므로 집 공유기 확인 후 개인 네트워크·방화벽 설정이 필요할 수 있다.
- `node db-view.js`가 실제 DB 건수만 출력했고, 공기계 테스트 담당자 토큰을 `private/LOCAL_TOKENS.txt`에 발급·저장했다. 토큰 원문은 이 문서에 기록하지 않는다.
- PC 웹 대화방에 승인된 채팅 사진·수락 후 영상·상대 프로필 사진 뷰어를 추가했다. 공기계 A가 업로드하고 PC 브라우저 B가 승인 후 **승인된 미디어 보기 / 새로고침**으로 확인한다. 방 변경·종료·로그아웃 시 임시 미디어 URL을 폐기한다. 웹 문법 검사와 통합 테스트 16개 통과, 실제 미디어 표시 기기 시험은 남았다.
- 서버의 `/app.apk`에서 빌드된 디버그 APK를 공기계 브라우저로 직접 내려받을 수 있다. `start-phone.ps1`이 다운로드 주소를 보여 주며 README에 USB 복사 대안도 적었다. 다운로드 응답의 바이트·헤더·파일 없음 처리를 통합 테스트에 추가했다. 실행 중인 LAN 서버를 재시작했고 다운로드 200 응답의 SHA-256이 원본 APK와 일치했다.
- Android 앱에 **서버 연결 확인** 버튼을 추가했다. 연결 성공 주소만 앱 설정에 저장해 다음 실행 때 자동 입력한다. 사용자 토큰은 여전히 실행 중 메모리에만 둔다. 새 APK 빌드·v2/v3 서명 검증·DEX 문자열 확인·실행 중 서버 다운로드 해시 일치를 확인했다. 연결된 ADB 기기와 AVD는 없어 실제 화면 시험은 남았다.
- `db-view.js`를 초보자용 읽기 전용 SQLite 조회 도구로 확장했다. `summary`, `users`, `rooms`, `messages <방 ID>`, `schema`, `sql "SELECT ..."`만 제공하며 목록은 20건으로 제한한다. 실제 DB에서 건수·목록·집계 SELECT를 확인했고 DELETE는 실행 전에 거부됨을 확인했다. README와 API_GUIDE에 순서·예시·개인정보 주의점을 적었다.
- 2026-09-21 후속 확인: 일시 중지됐던 LAN 서버를 `start-phone.ps1`로 다시 시작했다. `http://192.168.0.2:3000/api/health`와 `/app.apk`가 모두 200 응답하며 APK 크기는 24,985바이트다.
- 현재 이더넷 프로필은 Public, Windows 방화벽은 켜져 있다. `enable-home-phone-access.ps1`을 추가했다. 집 공유기임을 사용자가 확인해 개인 프로필로 바꾼 뒤 관리자 PowerShell에서 실행하면 개인 프로필·LocalSubnet·Node.js·TCP 3000만 허용한다. 이 스크립트는 자동 실행하지 않았다.
- `check-phone-ready.ps1`을 추가했다. 설정을 바꾸지 않고 PC 사설 주소·네트워크 프로필·APK 파일·토큰 메모 파일·서버 응답·APK 주소·방화벽 규칙을 한 번에 점검한다. README에 공기계 설치 전 실행 순서를 적었다.
- `check-phone-ready.ps1` 실제 실행 결과: PC 주소·APK 24.4KB·토큰 메모·`/api/health`·`/app.apk`는 OK. 현재 Windows 네트워크는 Public이고 개인 네트워크 방화벽 규칙은 아직 없다고 정확히 안내했다. Windows PowerShell용 UTF-8 BOM 인코딩도 적용했다.
- Notion 자동화가 실패할 때 바로 붙여넣을 `NOTION_UPDATE.txt`를 추가했다. 현재 구현·완료·다음 구현의 3문장으로 구성하며 토큰 원문은 포함하지 않는다.
- 공기계 브라우저용 `/install` 페이지를 추가했다. 현재 접속한 PC 주소를 앱 입력 주소로 보여 주고, `/app.apk` 다운로드·설치·서버 연결 확인 순서를 안내한다. 서버를 재시작해 `/install`, `/api/health`, `/app.apk` 모두 200 응답을 확인했다. 통합 테스트는 설치 안내 페이지 검증을 포함해 17개 통과했다.

## 2026-09-20 확인한 상태

- 위치: 바탕화면 `RandomChat` 폴더. Node.js 22, `sharp` 설치 필요(`npm ci`).
- 로컬 서버: `start.cmd` 또는 `node server.js` 실행 후 `http://127.0.0.1:3000`.
- 데이터: `data/chat.sqlite`에 저장. 기존 사용자의 데이터는 삭제하거나 초기화하지 않음.
- 구현: 랜덤 1:1 텍스트 대화, 연결 요청/수락/거절/취소, KST 하루 무료 2건, 수락 후 프로필 소개 공개, 차단·신고.
- 이번 변경: `clientId`로 메시지 100회 재전송 시 DB 1건, 다른 본문으로 식별자 재사용 거부. 연결 수락 100회 재시도 시 차감 1건. 로컬 계정 삭제 시 토큰 폐기·소개/본인 메시지 삭제·활성 방 종료. 기존 SQLite DB에 `client_id`, `deleted_at` 컬럼을 추가하는 마이그레이션.
- 신고 처리: `admin.js`에서 로컬 담당자 토큰 발급·배정·폐기. 일반 사용자 토큰은 운영 API에 접근할 수 없고, 배정 담당자만 신고 사유를 열람·종결한다. 목록에는 사유가 없으며 열람·종결·배정 기록을 DB에 남긴다. 기존 신고는 미배정 사건으로 이전한다.
- 신고 검토 화면: `/review`에서 담당자 토큰을 입력하고 배정 목록·사유·처리 기록을 본다. 토큰은 브라우저 저장소에 넣지 않고 화면 메모리에만 둔다. 사건을 열면 서버가 열람 기록을 남긴다.
- 사진 검토·전달: 방 참가자가 5MB 이하 JPEG/PNG 원본을 보내면 재인코딩·메타데이터 제거 후 `pending`으로 격리한다. 로컬 명령에서 활성 담당자에게 배정하고 `/review`에서 열람 기록을 남긴 뒤 승인·거절한다. 승인본은 현재 방 참가자에게만 인증 API로 전달한다. 거절·본인 삭제·방 종료·차단·탈퇴 때 사진 바이트를 지운다.
- Android 로컬 앱: `android/src`의 네이티브 Java 화면에서 테스트 계정·매칭·텍스트·요청 수락/거절·차단/신고·사진 업로드·승인 사진 보기를 연결했다. `android/build.ps1`로 SDK 33/JDK 17 APK를 컴파일·서명 검증했다. 연결된 Android 기기/AVD가 없어 설치·실행은 아직 검증하지 못했다.
- 프로필 등록 사진: 채팅 첨부와 별도 테이블·담당자 검토·감사 기록을 사용한다. 승인 전은 본인 상태만 보이며, 승인 후에도 CONNECTED 방의 상대만 인증 API로 본다. 등록 사진은 방이 끝나도 본인에게 남고 탈퇴 때 삭제한다. Android 앱에 등록/조회 UI와 `FLAG_SECURE`를 추가했다.
- 수락 후 영상: 20초·720p·20MB 이하 MP4를 FFprobe로 검사하고 FFmpeg로 H.264/AAC MP4로 재인코딩한다. 별도 담당자 배정·열람 감사·승인 뒤 현재 CONNECTED 방에서만 조회한다. Android 파일 선택·임시 재생 UI를 빌드했다.
- Android 영상 업로드는 서버 변환 시간(최대 30초)을 기다리도록 응답 대기 시간을 60초로 설정했다. APK 재빌드·서명 검증은 완료했으며 실제 기기 업로드는 미검증이다.
- 종료 방 정리 도구: `node retention.js preview-ended <일수>`로 신고 없는 오래된 종료 방을 미리 본다. 정책 확정 후 서버를 종료하고 `purge-ended <일수> --apply`를 실행하면 SQLite 백업·무결성 검사 뒤 메시지·요청·방을 정리한다. 현재 바탕화면 DB에는 적용하지 않았다.
- 검증: 서버 통합 테스트 15개 통과. 영상의 수락 전 거부·형식 검사·담당자 승인·타인 접근 거부·차단 후 삭제와 종료 방 백업·신고 보존을 포함한다. APK 컴파일·서명 검증 완료. 기존 DB를 유지한다.

## 남은 기능

1. 공개 서비스용 대화/신고 기록 보관·삭제 정책 확정 및 백업 복원 뒤 삭제 재적용. 현재 계정 삭제는 로컬 데모 범위다.
2. 실제 연령/본인 확인 및 운영자 계정·MFA. 현재 가입 체크는 개발용 자기 확인이며 담당자 인증은 로컬 토큰 수준이다.
3. 미디어 보관기간·전송빈도 정책. 사진·영상 모두 서버 경로와 Android UI는 구현했지만 실기기 검증은 없다.
4. Android 기기 시험, 결제 및 출시 심사. 아직 없음.

## 다음 한 작업

Android 기기 또는 AVD에서 매칭→사진·영상 업로드→담당자 승인→상대 표시·재생→캡처 억제를 시험한다. 이어서 미디어 보관기간·전송빈도와 삭제 정책을 확정해 적용한다. 현재 로컬 토큰 기반 담당자 인증은 공개 서비스용 운영자 계정·MFA가 아니다.
