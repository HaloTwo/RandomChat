# 모먼트 — 로컬 랜덤채팅 P0

노션의 **개인 프로젝트 · 랜덤채팅 앱** 기획을 바탕으로 만든 개발용 앱입니다. PC가 서버와 SQLite DB를 실행하고, 공기계 APK는 같은 공유기의 PC 서버에 접속합니다. 외부 서비스에는 배포하지 않았습니다.

## 공기계로 실행: 이 순서대로 하세요

최근 수정: Android 라운지 사진/내 글 표시, LAN HTTP 웹 메시지 전송, 사진 업로드 실패 후 같은 글에 재시도, 피드 이미지 재다운로드 억제, Android 현재 방 새로고침을 수정했습니다. 자동 테스트 21개와 APK 빌드·서명 검증을 완료했습니다. 실제 공기계 설치·실행 테스트는 아직 하지 않았습니다.

### 관리자 대화 조회

1. PC 서버를 켜고 브라우저에서 서버 주소 뒤에 `/review`를 붙여 엽니다. 예: `http://192.168.0.2:3000/review`. 실제 주소는 서버 창의 주소를 사용하세요.
2. 바탕화면 `RandomChat` → `data` → `LOCAL_TOKENS.txt`를 메모장으로 열어 담당자 토큰을 복사합니다.
3. `/review`의 토큰 입력칸에 붙여넣고 로그인합니다.
4. **관리자 대화 조회**에서 방을 선택하면 현재 DB의 텍스트 메시지가 보입니다. 종료된 방도 조회할 수 있습니다.
5. 방은 50개씩, 메시지는 200개씩 표시합니다. 다음 목록/메시지 버튼으로 이어서 봅니다. 새 메시지는 방을 다시 선택해 확인합니다.
6. 사용 후 **토큰 지우기**를 누릅니다.

기존 활성 담당자 토큰 모두에 대화 조회 권한이 있습니다. 일반 사용자 토큰으로는 볼 수 없습니다. 본문 열람은 `conversation_access_audit`에 기록합니다. 삭제된 메시지는 복구하지 않으며 사진·영상은 기존 배정·검토 화면을 사용합니다.

### 0. 처음 한 번만 확인

- PC에 **Node.js 22 이상 LTS**가 있어야 합니다. 바탕화면 `RandomChat` 폴더에서 PowerShell을 열고 `node --version`을 입력했을 때 `v22...`가 보이면 됩니다. 이 PC에는 이미 설치되어 있습니다.
- SQLite, MySQL, MariaDB는 설치하지 않습니다. 서버가 `data/chat.sqlite` 파일을 자동으로 만듭니다.
- 공기계는 Android 8 이상이어야 합니다.

### 1. PC와 공기계를 같은 집 공유기에 연결

1. PC에서 VPN을 끕니다.
2. 공기계의 Wi-Fi를 켜고 **집에서 쓰는 Wi-Fi**에 연결합니다. `게스트`, `Guest`, `공용` Wi-Fi에는 연결하지 마세요.
3. PC는 같은 공유기의 Wi-Fi 또는 유선 이더넷에 연결합니다. PC가 유선이고 공기계가 Wi-Fi여도 같은 공유기면 됩니다.
4. PC의 Windows 설정 → **네트워크 및 인터넷** → 현재 연결한 이더넷 또는 Wi-Fi → **네트워크 프로필**을 엽니다. 집 공유기가 맞을 때만 **개인 네트워크**를 선택합니다.

### 2. PC에서 서버를 켭니다

1. 바탕화면의 `RandomChat` 폴더를 엽니다.
2. **`start-phone.cmd`를 더블클릭**합니다.
3. 주소 선택 화면이 나오면 공기계와 같은 공유기의 PC 주소를 선택합니다. 보통 `192.168.x.x` 주소입니다.
4. 다음처럼 보이는 주소를 그대로 메모합니다.

```text
PC/공기계 서버 주소: http://192.168.x.x:3000
공기계 APK 다운로드: http://192.168.x.x:3000/app.apk
```

5. 서버 창은 **닫지 말고 계속 켜 둡니다.** 이 창을 닫으면 공기계 앱도 서버에 연결할 수 없습니다.

### 3. PC 준비 상태를 확인합니다

`RandomChat` 폴더 빈 곳에서 **Shift + 마우스 오른쪽 버튼 → 터미널에서 열기**를 누른 뒤 아래를 입력합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\check-phone-ready.ps1
```

`PC 사설 주소`, `APK 파일`, `서버 응답`, `공기계 APK 주소`, `Windows 네트워크`, `개인 네트워크 방화벽 규칙`이 모두 `[OK]`면 다음 단계로 갑니다. 담당자 토큰 메모는 사진·영상 검토를 할 때만 필요합니다.

`Windows 네트워크` 또는 `개인 네트워크 방화벽 규칙`에 `[확인 필요]`가 보이면, **집 공유기라는 것을 확인한 뒤에만** 관리자 PowerShell을 열어 아래를 한 번 실행합니다.

```powershell
cd "$env:USERPROFILE\Desktop\RandomChat"
powershell -ExecutionPolicy Bypass -File .\enable-home-phone-access.ps1
```

실행 뒤 `check-phone-ready.ps1`을 다시 실행해 `개인 네트워크 방화벽 규칙`이 `[OK]`인지 봅니다.

### 4. 공기계에 APK를 설치합니다

1. 공기계 브라우저에서 2단계에 메모한 주소 뒤에 `/install`을 붙여 엽니다. 예시는 아래와 같습니다.

```text
http://192.168.x.x:3000/install
```

2. 설치 안내 페이지가 열리면 **APK 다운로드**를 누릅니다.
3. 다운로드가 끝나면 파일 앱의 `Download` 폴더에서 `moment-local-debug.apk`를 누릅니다.
4. 설치를 막으면 브라우저 또는 파일 앱에 대해 **이 출처의 앱 설치 허용**을 켭니다.
5. 설치가 끝나면 **모먼트** 앱을 실행합니다.

공기계 브라우저에서 설치 페이지가 열리지 않으면, 먼저 같은 브라우저에서 `http://PC주소:3000/api/health`를 엽니다. `{"ok":true}`가 보일 때만 APK 설치를 진행하세요. 그래도 안 열리면 1단계와 3단계를 다시 확인합니다.

### 5. 공기계 앱을 PC 서버에 연결합니다

1. 앱의 **서버 주소** 칸에 2단계에서 메모한 주소를 그대로 붙여넣습니다. 예: `http://192.168.x.x:3000`
2. **서버 연결 확인**을 누릅니다.
3. `서버 연결 성공`이 보이면 **테스트 계정 만들기**를 누릅니다.
4. 앱을 완전히 종료하면 개발용 사용자 토큰은 지워집니다. 다시 실행한 뒤에는 새 테스트 계정을 만들면 됩니다. 성공한 서버 주소만 기기에 남습니다.

### 6. PC 브라우저에서 상대 테스트 계정을 만듭니다

1. PC 브라우저에서 `http://127.0.0.1:3000`이 아니라 2단계의 PC 주소를 엽니다. 예: `http://192.168.x.x:3000`
2. 공기계 계정과 다른 닉네임으로 테스트 계정을 만듭니다.
3. 공기계와 PC 브라우저가 각각 한 명의 사용자입니다. 이제 아래 **실제 플레이 예시**를 순서대로 진행합니다.

**APK만 설치해서는 매칭되지 않습니다.** 서버와 DB는 PC에서 실행되므로 PC가 켜져 있고 `start-phone.cmd` 창이 열려 있어야 합니다. 인터넷 공개 서버나 결제 계정은 없습니다. 다른 사람의 Wi-Fi, 공용 Wi-Fi에서 이 개발용 서버를 열지 마세요.

### 공기계 설치 전 10초 점검

아래 명령은 설정을 바꾸지 않고 PC 주소, 서버 응답, APK 주소, 토큰 메모, 네트워크 프로필과 방화벽 규칙만 확인합니다.

```powershell
cd "$env:USERPROFILE\Desktop\RandomChat"
powershell -ExecutionPolicy Bypass -File .\check-phone-ready.ps1
```

`[OK]`가 모두 나오면 공기계에서 APK 주소를 열면 됩니다. `Windows 네트워크`나 `개인 네트워크 방화벽 규칙`이 `확인 필요`라면 아래 연결 문제 해결 순서를 진행하세요.

**공기계에서 서버 연결이 안 되면:** PC 화면의 서버 주소가 공기계에 입력한 주소와 같은지, 두 기기가 같은 공유기에 있는지 확인하세요. 공기계 브라우저의 `/api/health`도 열리지 않으면 Windows의 해당 **이더넷/Wi-Fi 네트워크 프로필**을 확인합니다. 본인 집 공유기임을 확인한 경우에만 Windows 설정 → 네트워크 및 인터넷 → 이더넷 또는 Wi-Fi → 해당 연결 → **개인 네트워크**로 바꾸세요. 그다음 `enable-home-phone-access.ps1`을 **관리자 PowerShell**에서 한 번 실행합니다.

```powershell
cd "$env:USERPROFILE\Desktop\RandomChat"
powershell -ExecutionPolicy Bypass -File .\enable-home-phone-access.ps1
```

이 스크립트는 개인 네트워크의 같은 공유기 기기에서만 Node.js TCP 3000 접속을 허용합니다. 공용 네트워크에서는 규칙을 만들지 않습니다. 나중에 지우려면 관리자 PowerShell에서 `Remove-NetFirewallRule -DisplayName 'RandomChat Home TCP 3000'`을 실행하세요. 이 PC의 현재 이더넷 연결은 공용으로 표시되어 있어 공기계 접속은 아직 검증되지 않았습니다.

### 실제 플레이 예시: 공기계 A와 PC 브라우저 B

1. 공기계 A에서 **오늘의 라운지**의 `24시간 스토리` 또는 `게시물`에 글을 적고 **올리기**를 누릅니다. 사진을 붙이려면 `사진 선택·올리기`를 누르고 JPEG/PNG를 고릅니다.
2. PC 브라우저 B에서 같은 서버 주소로 새 테스트 계정을 만든 뒤 라운지를 새로고침합니다. A가 쓴 게시물과 스토리가 보입니다. A는 앱에서 **내 게시물 삭제** 또는 **내 스토리 삭제**를 눌러 본인 글만 지울 수 있습니다.
3. 공기계 A에서 **랜덤 대화 찾기**를 누릅니다. 화면에 상대를 기다린다는 메시지가 나옵니다.
4. PC 브라우저 B에서 **랜덤 대화 찾기**를 누릅니다. 공기계의 **새로고침**을 누르고 대화방을 선택합니다.
5. A에서 메시지를 보내고 B에서도 답합니다. 수락 전에는 서로의 프로필 소개·사진이 보이지 않습니다.
6. A에서 **계속 대화 요청**, B에서 **요청 수락**을 누릅니다. 공기계 A의 **새로고침**을 누릅니다. A가 신청자라면 그때 하루 무료 연결 2건 중 1건이 차감됩니다.
7. A에서 사진을 선택해 올립니다. PC PowerShell에서 아래 **사진 검토 예시** 순서로 승인합니다. PC 브라우저 B의 대화방에서 **승인된 미디어 보기 / 새로고침**을 누르면 사진이 표시됩니다.
8. 연결된 방에서만 A가 짧은 MP4 영상을 올릴 수 있습니다. **영상 검토 예시**대로 승인한 뒤 B의 같은 버튼을 누르면 영상이 표시되고 재생할 수 있습니다. A가 프로필 사진을 올려 승인받으면 B에서 연결된 방의 같은 버튼으로 볼 수 있습니다. PC 웹은 미디어 조회용이며 업로드는 Android 앱에서 합니다.

### 사진·영상 검토 예시 (PC PowerShell)

`RandomChat` 폴더에서 PowerShell을 열고, 담당자 토큰을 아직 만들지 않았다면 아래 첫 명령을 한 번 실행합니다. 토큰은 `data/LOCAL_TOKENS.txt`에 저장되며 PC 메모장으로 열 수 있습니다.

```powershell
node admin.js create-reviewer-to-file "테스트 담당자"
node admin.js list-photos
node admin.js assign-photo <목록에서 나온 사진 ID> <담당자 ID>
```

PC 브라우저에서 **3번의 PC 주소 뒤에 `/review`를 붙여** 열고 메모장의 토큰을 입력해 사진을 열어 본 뒤 승인합니다. 영상은 `node admin.js list-videos`와 `node admin.js assign-video <영상 ID> <담당자 ID>`를 같은 방식으로 실행하고 `/review`의 영상 구역에서 승인합니다. `<...>`는 실제 ID로 바꾸고 꺾쇠는 입력하지 않습니다. 검토 전 파일은 상대에게 표시되지 않습니다.

### SQLite와 토큰은 어디에 있나요?

- SQLite는 **앱에 포함된 DB 방식**이라 별도 SQL 서버, 계정, 비밀번호가 필요하지 않습니다. 이 프로젝트에서는 MySQL·MariaDB·SQLite 프로그램을 추가로 받을 필요가 없습니다. 데이터 파일은 `data/chat.sqlite`이며 서버를 처음 켜면 자동으로 생성됩니다. DB 파일은 메모장으로 열거나 공유하지 마세요.
- 토큰/API 설명은 [API_GUIDE.txt](API_GUIDE.txt)에 모았습니다. 담당자 토큰 원문은 `node admin.js create-reviewer-to-file "테스트 담당자"` 실행 후 **`data/LOCAL_TOKENS.txt`**에만 저장합니다. Android 사용자 토큰은 앱 실행 중 메모리에 있으며 API 호출 때 자동으로 붙습니다. 종료 후 복구할 수 없어 새 개발용 계정을 만들어야 합니다.
- `data/`는 Git에서 제외됩니다. 토큰 메모와 DB 백업도 그 안에 있으니 외부에 보내지 마세요.

### SQLite를 직접 확인하는 순서

1. `RandomChat` 폴더 빈 곳에서 **Shift + 마우스 오른쪽 버튼 → 터미널에서 열기**를 누릅니다.
2. 아래 명령을 입력하면 DB를 바꾸지 않고 테이블별 건수만 봅니다. 이 명령에는 메시지·신고 사유·토큰 원문이 나오지 않습니다.

```powershell
node db-view.js
```

예시 출력은 `users: 2건`, `rooms: 1건`, `messages: 3건`처럼 표시됩니다.

3. 테스트 계정과 최근 방만 보고 싶으면 아래를 입력합니다. `rooms` 결과의 `id`는 다음 단계에서 메시지를 볼 때 사용하는 방 ID입니다.

```powershell
node db-view.js users
node db-view.js rooms
node db-view.js posts
node db-view.js stories
```

4. 특정 방의 메시지 본문을 확인할 때만 아래처럼 방 ID를 넣습니다. 화면이나 출력에는 개인 내용이 보일 수 있으니 외부에 보내지 마세요.

```powershell
node db-view.js messages 여기에-rooms-목록의-방-ID-붙여넣기
```

5. 직접 SQL을 연습하고 싶으면 `SELECT` 조회문만 허용합니다. `INSERT`, `UPDATE`, `DELETE`, `DROP`은 이 도구에서 실행되지 않습니다.

```powershell
node db-view.js sql "SELECT status, count(*) AS count FROM rooms GROUP BY status"
node db-view.js schema
```

처음부터 다시 테스트해야 한다면 서버를 종료한 뒤 `data/chat.sqlite`를 지우는 방식입니다. 기존 테스트 데이터도 함께 사라지므로 필요하면 먼저 `data/backups/`에 복사하세요.

### PC 브라우저만 시험하기

`start.cmd`를 더블클릭하면 `127.0.0.1:3000`에서만 실행됩니다. 서로 다른 두 브라우저 창 또는 일반/시크릿 창에서 각각 테스트 사용자를 만들고 한쪽이 먼저 **랜덤 대화 찾기**를 누릅니다. `start.cmd`와 `start-phone.cmd`는 동시에 실행할 수 없습니다(같은 3000번 포트).

대화 데이터는 `data/chat.sqlite`에 저장됩니다. 데이터 초기화가 필요하면 서버를 종료한 뒤 해당 파일을 삭제하세요.

## 현재 구현

- 실제 대기 사용자끼리 랜덤 1:1 매칭, 텍스트 메시지, 최근 대화 열람
- 메시지 식별자 기반 재전송 처리. 응답이 끊겨 같은 메시지를 다시 보내도 DB에 한 건만 기록
- 계속 대화 요청·수락·거절·취소, 5분 또는 KST 자정까지의 요청 예약
- 수락 재시도에도 연결 상태와 무료 차감은 한 번만 반영
- 신청자 기준 하루 무료 연결 2건. **수락될 때만** 소비
- 서로 수락하기 전 프로필 소개 비공개, 수락 뒤 상호 공개
- 대화 종료, 차단, 종료 후 신고 기록
- 로컬 신고 처리: 담당자 배정, 배정된 신고만 열람·종결, 사건 열람·처리 감사 기록
- `/review` 운영 검토 화면: 배정된 신고·사진·영상만 열람하고 처리 기록 저장
- Android 클라이언트 준비용 사진 API: JPEG/PNG를 재인코딩해 승인 전 격리, 담당자 승인 후 활성 대화방 참가자에게만 전달
- 프로필 사진은 채팅 첨부와 별도 검토·저장. 승인 후에도 연결을 수락한 상대만 현재 방 권한으로 조회
- 수락 후 영상: 20초·720p·20MB 이하 MP4를 검사·재인코딩하고 담당자 승인 뒤 현재 연결 방 참가자에게만 전달
- Android 로컬 디버그 앱: 테스트 계정·라운지 게시물/24시간 스토리·사진 첨부·매칭·텍스트·연결 요청/수락·신고/차단·채팅/프로필 사진·승인 영상 재생. `FLAG_SECURE` 적용, 기기 실행 검증은 아직 없음
- PC 웹: 같은 대화방의 승인된 채팅 사진·수락 후 영상·상대 프로필 사진을 인증된 API로 조회. 미승인 파일은 건수만 표시하며 업로드는 Android 앱에서 진행
- PC 웹 라운지: 로그인한 로컬 테스트 사용자끼리 게시물(글 500자·사진 1장)과 24시간 스토리(글 120자·사진 1장)를 올리고, 본인 콘텐츠를 삭제. 사진은 최대 5MB JPEG/PNG를 정규화한 JPEG로 저장
- 로컬 계정 삭제: 토큰 폐기, 소개·본인 메시지 삭제, 활성 대화 종료
- SQLite 저장, 인증 토큰 해시 저장, 방 참가자만 메시지 접근
- 종료된 방의 보관 정리 미리보기와 선택 실행 도구. 실행 전 SQLite 백업·무결성 확인, 신고가 있는 방은 제외

## 아직 구현하지 않은 범위

사진·영상 검토는 사람이 `/review`에서 직접 승인·거절하는 로컬 흐름이며 자동 내용 판정은 없습니다. 공개 라운지의 게시물·스토리는 로컬 테스트 로그인 사용자에게 즉시 보이는 데모 기능이라, 실제 공개 전에는 신고·차단 범위와 콘텐츠 심사 정책을 별도로 구현해야 합니다. Android APK도 라운지 작성·사진 업로드·열람·삭제를 포함하지만 연결된 기기가 없어 설치·화면·미디어 표시·캡처 억제를 기기에서 검증하지 못했습니다. 실제 연령/본인 인증, 운영자 계정·MFA, 결제, 출시용 Android 빌드는 아직 없습니다. 검토 화면은 로컬 토큰 기반이며 실제 운영 조직의 인증 절차가 아닙니다. 가입 화면의 성인 체크는 **개발용 자기 확인**입니다. 계정 삭제는 로컬 데모에서 본인 메시지와 소개를 지우며, 상대가 작성한 메시지는 상대 계정에 남습니다. 삭제한 계정의 난수 ID와 과거 연결권 기록은 중복 차감 판정을 위해 DB에 남습니다. 이 보존 규칙은 공개 서비스 정책으로 확정한 것이 아닙니다.

개발용 앱이므로 개인정보나 실제 사용자 대화를 입력하거나 외부에 공개하지 마세요. `start.cmd`는 로컬호스트, `start-phone.cmd`는 선택한 PC의 사설 IP에만 바인딩됩니다.

## 종료된 대화 데이터 정리

`node retention.js preview-ended 30`은 종료 후 30일이 지난 방 중 신고가 없는 방의 메시지·요청·미디어·방 건수를 보여 줍니다. **30일은 명령 예시일 뿐 확정 보관기간이 아닙니다.** 2~3650일 중 운영 정책에 맞는 값을 명시해야 합니다. 신고가 하나라도 있는 방은 종결 여부와 관계없이 제외됩니다.

정책이 확정된 뒤 서버를 종료하고 `node retention.js purge-ended 30 --apply`를 실행하면 `data/backups/`에 SQLite 백업을 만든 뒤 무결성을 확인하고 대상 방을 한 트랜잭션에서 정리합니다. 백업에는 정리 전 대화 데이터가 남으므로 별도 접근·보관·삭제 정책이 필요합니다. 현재 바탕화면 DB에는 이 삭제 명령을 실행하지 않았습니다. 프로필 사진, 신고·감사 기록, 탈퇴 ID의 보존 정책도 별도로 정해야 합니다.

## Android 로컬 디버그 앱

`android/build/moment-local-debug.apk`를 빌드했습니다. 이 PC의 Android SDK 33과 Unity 포함 JDK 17로 `powershell -File android/build.ps1`을 실행해 다시 만들 수 있습니다. APK에는 로컬 서버 연결용 평문 HTTP만 허용됩니다.

- 에뮬레이터: 서버를 켠 뒤 앱의 기본 주소 `http://10.0.2.2:3000`을 사용합니다.
- USB 기기: `adb reverse tcp:3000 tcp:3000` 후 앱 주소를 `http://127.0.0.1:3000`으로 바꿉니다. `adb install -r android/build/moment-local-debug.apk`로 설치합니다.
- 공기계 Wi-Fi: 위 **처음 실행** 순서대로 `start-phone.cmd`를 켜고 앱에 표시된 PC의 사설 IPv4 주소를 입력합니다. USB 디버깅이나 ADB 설치는 필요 없습니다.
- 두 사용자를 별도로 만들고 매칭 → 메시지 → 사진 업로드 → `node admin.js list-photos`와 `assign-photo` → `/review` 승인 → 앱 새로고침에서 승인 사진 보기를 확인합니다.

이 PC에는 현재 연결된 Android 기기나 에뮬레이터가 없어 APK 서명·패키지 검증까지만 완료했습니다. 앱 토큰은 실행 중 메모리에만 있고 종료하면 사라집니다.

## 확인

`npm test`로 게시물·스토리의 로그인 접근·소유자 삭제·24시간 만료·사진 정규화와 함께 매칭·프로필 공개·무료 차감·차단·방 접근·메시지 재전송·계정 삭제·신고 접근 권한·채팅/프로필 사진의 분리된 검토와 공개 권한·기존 DB 마이그레이션을 검증합니다. 브라우저 두 탭에서는 `가`와 `나`를 만들고 매칭 → 메시지 → 계속 대화 요청 → 상대 수락 → 프로필 공개와 무료 잔여 1건을 확인하면 됩니다.

## 사진 승인 흐름

`POST /api/rooms/<방 ID>/photos`에 로그인 토큰과 `Content-Type: image/jpeg` 또는 `image/png`로 최대 5MB의 **원본 바이트**를 보냅니다. 서버는 실제 형식·정지 이미지 여부·픽셀 상한을 검사하고 최대 1600px JPEG로 재인코딩해 `pending`으로 저장합니다. `node admin.js list-photos`에서 ID를 확인하고 `node admin.js assign-photo <사진 ID> <담당자 ID>`로 배정합니다. 담당자는 `/review`에서 사진을 열어 내용 검토 후 승인하거나 거절합니다. 승인 전에는 올린 사람만 메타데이터를 보고, 거절하면 사진 바이트를 삭제합니다. 승인 후 `GET /api/rooms/<방 ID>/photos` 목록과 인증된 `GET /api/photos/<사진 ID>`에서 현재 방 참가자만 정규화한 JPEG를 받습니다. 이 응답은 캐시하지 않습니다. `DELETE /api/photos/<사진 ID>`는 본인 업로드를 삭제합니다. 방 종료·차단·탈퇴 때 관련 사진을 삭제합니다. PC 웹 대화방의 **승인된 미디어 보기 / 새로고침**에서 승인된 사진을 볼 수 있습니다.

## 로컬 신고 처리

`node admin.js create-reviewer-to-file <이름>`으로 담당자 토큰을 발급·로컬 메모에 저장하고, `node admin.js list-reports`에서 신고 ID를 찾은 뒤 `node admin.js assign <신고 ID> <담당자 ID>`로 배정합니다. 담당자는 PC의 서버 주소 뒤 `/review`에서 메모의 토큰을 입력해 배정된 사건을 검토하고 처리 기록을 남깁니다. 목록에는 신고 사유가 나오지 않으며 상세 열람과 종결은 `admin_access_audit`에 남습니다. `node admin.js revoke-reviewer <담당자 ID>`로 토큰을 폐기합니다. 토큰은 `data/LOCAL_TOKENS.txt`에만 두고 노션·공유 저장소에 적지 않습니다.

## 프로필 사진

`POST /api/profile/photos`로 본인 사진을 등록하면 `pending`으로 격리합니다. `node admin.js list-profile-photos`에서 ID를 찾고 `assign-profile-photo <사진 ID> <담당자 ID>`로 배정합니다. 담당자는 `/review`의 **프로필 등록 사진** 구역에서 열람 후 승인·거절합니다. `GET /api/profile/photos`는 본인 상태를 반환하고, `DELETE /api/profile/photos/<ID>`는 본인 사진을 삭제합니다. 상대는 연결 수락 후에만 `GET /api/rooms/<방 ID>/peer/profile-photos`와 그 아래 `<사진 ID>` 경로에서 승인본을 받습니다. 랜덤 방·종료된 방·다른 방에서는 조회할 수 없습니다. 탈퇴하면 등록 사진을 삭제합니다.

## 수락 후 영상

연결을 수락한 방에서만 `POST /api/rooms/<방 ID>/videos`에 `Content-Type: video/mp4`로 최대 20MB 원본을 보냅니다. 서버는 실제 MP4와 영상 길이 20초·해상도 1280×720 이하를 검사하고 H.264/AAC MP4로 다시 인코딩합니다. 변환본은 8MB 이하이며 `pending`으로 격리합니다. `node admin.js list-videos`에서 ID를 확인하고 `assign-video <영상 ID> <담당자 ID>`로 배정합니다. 담당자는 `/review`에서 영상을 열어 감사 기록을 남긴 뒤 승인·거절합니다. 승인 후 현재 연결 방 참가자는 `GET /api/rooms/<방 ID>/videos`와 인증된 `GET /api/videos/<영상 ID>`로 열람합니다. 종료·차단·탈퇴·거절 시 영상 바이트를 지웁니다. `DELETE /api/videos/<영상 ID>`는 본인 업로드를 삭제합니다. 보관기간과 전송빈도는 공개 서비스 전 별도 확정이 필요합니다.

다음 구현 순서와 재개 방법은 [HANDOFF.md](HANDOFF.md)에 기록합니다.
